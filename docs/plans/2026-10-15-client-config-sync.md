# 多客户端配置与原生能力复核

## 范围

为现有 AI 资源中心明确多客户端入口、Magpie 原生同步、fn 无头 Hub 和客户端限定渠道的轻量方案。交付复核和设计修正；不部署新 Hub，不修改生产渠道、客户端或 WebDAV 设置。

## 当前决定

- 保留 fn New API/CPA 和酒馆的现有职责。普通应用使用稳定 fn 入口，各应用分开推理身份；RP 直连、人工管理、禁主动测试。
- 客户端配置与连接库共享复用 Magpie 原生适配和 WebDAV。各机独立选模型时使用 agents=no；本轮没有更改现有 agents=true。
- Linux/Docker Magpie 已具备无头网关、Web UI、Remote Magpie、设备网关密钥、模型限制和路由。集中使用其多账号/订阅时可直接选用，不需要新配置源。
- 只为保留客户端特征不新增 Hub。当前 New API 同协议正文及请求头透传通过自有 stub 验证；异常连接可用现有 Nginx Proxy Manager 固定代理。
- 自动测试的排除必须按实际任务模式核对；auto_ban=0 不等于通用禁测。不为新增渠道默认改变全局规则。
- 自动组、轮询及失败切换复用现成能力；七天质量评价、权益规则和人工决定继续归中心。单次请求链只使用一个资源池选路。
- 撤销上一版首选的新增 Magpie 配置源、托管缓存、设备领取及发布/回执接口。具体设备的实际调用保留来源与时间，不假设同步即生效。
