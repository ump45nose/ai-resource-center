# New API 聚合与渠道调用统计

## 范围与决定

按用户最新选择，由 fn New API 聚合普通资源和允许转发的客户端限定资源；Code 按所需客户端及协议分组，保留原生正文、客户端请求头和上游真实模型名。RP 继续酒馆直连，导入、编辑及同步不主动请求上游。明确禁止网关转发、协议或模型未确认的连接保留待处理原因，不冒充已接入。

中心每分钟读取已有网关日志，按来源记录标识去重；展示渠道、模型、应用调用身份、结果、延迟、首字时间、流式状态及 Token 数。未知应用明确显示，采集缺口直接可见；不保存提示词、请求正文或完整响应，不重复 Token Monitor 费用账本。已有 CPA 持久化采集继续读取 Manager 存储，不消费其用量队列。

New API 当前自动测试为 passive_recovery；新增客户端渠道设 auto_ban=0，正常状态不参加此模式的主动测试。接入前核对模式，不能把 auto_ban=0 单独当作禁测活。既有渠道和客户端默认配置保持，凭据加密保存。

## 验收

- Code 接入独立原生协议组，正文和头透传、认证替换正确；RP 不能接入公共池。
- 导出使用 fn 地址、独立推理身份和正确模型限制；不下发上游 key，不跨客户端混用。
- 调用来源隔离、幂等；分页明细、筛选与按渠道/模型/应用聚合一致，未关联记录有数量及原因。
- 记录不足、限流、额度或认证问题不误判长期质量；客户端候选只在自己的组中比较。
- fn 数据升级、部署、网关回读及真实日志同步验证通过；公网站点未成功生成保持原错误，不虚报健康。
