# AI 资源管理中心实施记录

## 目标与边界

独立 Web 中心在 fn 存储资源、签到、权益、连接规则与渠道评价。New API 和 CPA 保留各自推理入口；酒馆直连 RP 上游；客户端绑定资源保留原客户端协议与请求头。Token Monitor 继续承担用量统计。Personal Data Hub 不作为依赖。

RP 独占，非 RP 可在 Code、Hermes Chat/Cron 等应用间复用。客户端绑定资源独立维护，不强制套用公共网关分类。

## 决定

- React/TypeScript/Vite/Tailwind 前端，Node 24/Fastify/SQLite 单实例后端。
- fn 内网端口 18321，数据和密钥在持久卷，推理请求不经过中心。
- 先完成详细设计和 Figma Make 交互稿，验收后接回源码开发。
- 自动评价只依据真实调用与指定渠道任务，不增加签到或推理测活。
- 7 天窗口、30 条有效记录、98%/95% 分档；同档同模型首字延迟影响权重。
- All API Hub 上报自动、重试、手动和快速签到结果；离线持久排队、幂等接收。
- RP 保存/同步使用已有原生连接流程，版本冲突直接展示。
- 工作区隔离集成改动，保留现有未提交修改。不自动提交上游 PR。

## 验收

重复签到事件不重复记账；网络断开不重签；当日额度按已确认的时区到期；站点聚合和余额不重复；样本不足不改路由；限流/账号/余额与质量分离；评估任务固定渠道；RP 操作不访问上游；请求头进入实际目标请求；冲突不覆盖；网关修改回读；中心停机不影响已有推理。
