# 酒馆真实调用采集

## 目标与决定

RP 真实调用纳入中心统计，继续酒馆直连与人工管理。复用现有 RP 扩展，在实际生成请求时固定原生连接与地址快照，观察原生消费者读取的结果，记录完成、失败、取消、耗时、首字和上游已报告 Token。上报只含调用元数据；保存、导入、排序和同步不触发模型或目录请求。

酒馆 stats.json 只有角色统计。聊天 JSONL 含模型、生成时间、首字时间及部分本地 token_count，没有可靠历史站点与失败记录。历史数据从 fn 本地抽取元数据，来源标为历史留存、终态未知；模型无法唯一证明站点，不按当前配置倒推历史渠道。本地 Token 估算单列，不与上游 Token 相加。

实时使用现有 RP 来源和限定凭据。来源原生 profile 标识可唯一关联时复用导入关系；原生地址已变或关联不明则保留为待关联，不能归到旧渠道。开始事实与终态按同一调用标识更新，重复提交不增加计数；浏览器未交回终态保持待终态，不算成功或站点失败。

## 验收

- 单次原生生成只发送一次原请求，正文、认证与响应字节保持；流式逐块处理，不复制完整响应。
- 完成、HTTP/流内错误、取消和断流各有记录；上报失败不改变原生生成结果，离线后可重交。
- RP 凭据仅能写授权 RP 连接，输入不接受任务正文；实际调用的模型不受选定模型列表限制。
- 历史抽取只上传元数据，重复导入不重复计数；本地估算和上游 Token 分开。
- 中心显示 RP 来源、筛选、结果及人工管理状态；RP 不参与自动提降权或测试。
- 隔离酒馆验证生成、断网重交及失败；生产部署只更新采集扩展与来源设置，不以 RP 上游测活验收。
