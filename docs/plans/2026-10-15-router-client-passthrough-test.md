# AnyRouter / AgentRouter 真实客户端透传验证

## 目标与范围

用真实 Claude Code 对两个站点分别做直连和 New API 透传对照，判断 fn New API 是否保留站点要求的客户端特征。使用当前 fn 镜像的隔离实例，固定各站点渠道，不混入生产选路。测试采用短任务，不读取项目文件，不使用 RP 资源。

## 方法

从现有已授权的资源清单和客户端配置取凭据，不把 key、完整任务正文、认证头或完整响应写入报告。原客户端请求经 fn 的测试转发点直连或进入隔离网关，统一上游出口，记录必要请求特征与错误摘要。网关开启同协议正文透传和请求头透传，并使用单次固定渠道身份。

每站先做直连基线与网关对照；遇到限流、资源池耗尽或模型错误按事实分开记录。只有需要区分真实差异时才追加相同条件的确认请求。站点未给出成功基线时，不把限流或额度不足当作客户端特征丢失。

## 验收与清理

- [x] 确认两站凭据、地址、认证和模型来源。AnyRouter 使用现有 Magpie key；AgentRouter 从已保存 All API Hub 账号读取现有推理 key。
- [x] 真实 Claude Code 2.1.299 完成两站的对照；AnyRouter 按错误启用原生 1M，并换现有模型和站点提示的模型作确认。
- [x] 5 组网关对照的正文和客户端头完全保留；AnyRouter 429/供应不足、AgentRouter 402，均未验证成功生成。
- [x] 清理隔离网关、数据卷、临时推理身份及测试配置，保存脱敏结果。

不改变生产网关、已有客户端默认配置或站点的用途分类。实测结论再反馈到同步设计。

实际共 10 次公网推理，后续 CLI 重试复用原错误而不追加公网调用。结果见 [真实客户端对照](../verification/router-client-features.md)。
