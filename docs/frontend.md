# WebUI：真实资源管理

WebUI 与 API 在 fn 的 `18323` 同源提供。沿用暖纸色、紧凑工具栏、固定侧栏和 Georgia／宋体衬线字体；侧栏没有来源卡片和滚动条。界面不再加载示例数据。

## 当前可以使用

- **站点**：按站点聚合账号和渠道，搜索网址／别名／模型，通过通用／生图／视频／酒馆四个入口查看；归档按网站打不开、无余额无签到、网站或 key 失效、调用不稳定、调用失败、暂停维护分开；展开账号与渠道。
- **渠道详情**：查看真实余额和签到历史、目录记录、历史任务及调用数量；编辑站点资料、用途分组、渠道备注和五种限制标签，保存到 fn。
- **模型**：合并同名模型的渠道入口，保留配置、目录和任务依据；未评价的能力不按品牌猜测。只列服务端判定已生效的模型（渠道 `activeModels`），页面不另算可用状态；站点搜索覆盖渠道的全部已知模型（`knownModels`）。
- **接入与同步**：配对 All API Hub、查看账号／余额／key 与最近上报；配置 New API 及管理凭据，检查授权，首次预览后导入；立即同步、开启／暂停定时同步，分别查看配置和调用的更新时间与错误。
- **扫描与测试**：选择渠道批量扫描目录，查看网站与 API 分开记录的状态；筛选认可模型并安排任务，查看验收及 New API 回读。维护设置可配置周期、候选范围和预算；已有 cron 只在完成单次配置与回执适配后绑定。维护／失败渠道保留历史，禁测活与媒体依赖明确显示。
- **签到与权益**：按账号查看原单位余额、规则及已收到的签到历史；独立签到入口随站点展示。

酒馆分组只在酒馆维护，不导入 New API；禁止测活的连接只采集真实调用。限制标签直接显示在状态列，不作为顶部分类。旧 RP 已转为“禁止测活 + 禁止代码”。酒馆选定模型的双向编辑留到酒馆接入，不在本轮覆盖其配置。

All API Hub 已支持生成私密接入文件、持续上报状态和 key 读取进度；账号详情显示余额观察、已有签到结果和 key 同步问题。酒馆目前仍展示迁入资料，新版持续上报留到下一批。CPA 不提供接入入口，也不安排同步。书签通过 `GET /api/v2/bookmarks` 获取同一份分类；页面可导出 HTML，`scripts/sync-chrome-bookmarks.mjs` 使用 Chrome 原生 API 整理已有收藏并保留备份。原本经 CPA 转发的公益渠道历史仍保留，不因停接 CPA 而丢弃。

## 开发入口

```sh
npm run dev
```

打开 `http://127.0.0.1:18322/`。Vite 默认将 `/api` 代理到 fn `http://192.168.31.201:18323`，浏览器使用同源会话。其他 API 地址通过 `ARC_API_TARGET` 指定。界面沿用原管理密码；访问凭据只通过专用表单交给服务端，不放进本地存储或源码。

`npm run build` 类型检查并构建 `dist/`。`npm start` 同时提供构建后的页面和 API，Docker 在构建阶段生成前端。

- `web/api.ts`：会话、标准 API、分页读取、错误文字和版本冲突处理。
- `web/data.ts`：真实响应类型和显示格式，不包含演示站点。
- `web/hooks.ts`：定时刷新。
- `web/workspace.tsx`：页面共用资料及动作。
- `web/App.tsx`：导航、读取和详情；`Login.tsx`、`SourcePanel.tsx` 为登录与来源设置。
- `web/ManagementPanel.tsx`：站点管理抽屉；账号、渠道和同步状态分别在 `AccountEditor.tsx`、`ChannelEditor.tsx`、`SyncStatus.tsx`。
- `web/pages/`：站点、模型、来源、检查记录及权益；扫描页的维护设置和模型测试在 `MaintenanceSettings.tsx`、`ModelTests.tsx`。

页面每分钟刷新资料；扫描页每 10 秒更新进度，过期的响应不覆盖新结果。手动编辑和来源同步完成后立即读取。修改有版本校验，正常来源观察不会增加渠道编辑版本；保存遇到版本冲突时自动读取最新资料并提示重新修改，其他 409 显示服务端说明。管理会话过期后重新登录，不退回演示数据。
