## 本项目：交付独立管理入口和同一套接口

WebUI 承担完整资源管理，默认按站点查看；来源接入、持续同步和扫描测试是主要操作入口。模型查询、资料编辑和 cron 绑定使用相同标准 API，前端不单独实现资源判断规则。

第一阶段即交付可用 WebUI 和基础 API／MCP，让用户先管理现有资源；Hub 可同时接入，不互相等待。自动维护和使用端联动完成时，同步补齐页面操作、进度与结果展示。

详细流程见[WebUI 需求](requirements.md#webui-围绕查资源选渠道和处理问题)。本项目负责自身界面，不修改 Hub 或酒馆 agent 的工作区。

## 给 Hub agent：你决定布局和接入深度

### 可直接使用的业务流程

| 流程 | 调用能力 | 用户应看到什么 |
| --- | --- | --- |
| 看日常资源 | overview、sites、models、attention | 可用模型、余额签到、当日权益和真正需要处理的问题；来源及更新时间 |
| 找模型对应的渠道 | models 筛选并打开站点 | 站方状态、自己的验证与实际表现分别显示，能跳转站点和签到入口 |
| 补 key、改资料、暂停 | 对象更新与受限凭据写入 | 保存结果；后续扫描／同步进度，不把保存直接显示为已验证 |
| 合并重复／批量整理 | 变更预览与应用 | 影响的账号、渠道和余额关系；不能把独立账号余额合并累计 |
| 检查和恢复 | scans、evaluations、operations | 当前步骤、等待原因、最终恢复的模型及 New API 生效结果 |
| 配置限时任务 | cron tasks 与 bindings | 选择已有任务和渠道模型；原暂停状态、时间调整和执行结果 |
| 编辑 RP | 酒馆绑定与关联渠道查询更新、同步状态 | 已保存／待同步／已应用／冲突；测试权限看“禁止测活”标签，保存不触发测试 |

Hub 原有登录保持不变，具体模块布局、原生或其他渲染方式由 Hub agent 决定。建议从资源摘要、待处理事项和站点查询开始；深度管理可以跳转独立 WebUI 的对应站点，也可以通过 API 自行提供操作界面。上表是可接入能力，不要求 Hub 重做全部管理页。

对“未签到”“无法签到”“浏览器尚未上报”“网站打不开”“API 失败”使用不同含义；自动维护中的已知问题不全都变成待办。技术错误放在相应记录，主提示提供能执行的动作。

**服务方交付**：OpenAPI、MCP 工具清单、示例响应、字段说明、联调地址、WebUI 对象链接与授权接入方式。**Hub 方完成条件**：按其选定范围展示真实资源和提醒，跳转到正确对象；若提供编辑，能正确显示保存、操作进度和冲突结果。

## 给酒馆 agent：双向同步连接，不改生成内容配置

独立联动插件使用 `/api/v2/rp/inventory`、`saves`、`credentials` 上报，
`/api/v2/rp/connections` 查询／修改绑定，`/api/v2/ingest/rp-calls` 回传终态。
配置下发与回执复用 `connector/jobs`、`connector/receipts`，不另建变化队列。
`/api/v2/access` 为 `rp` 与 `connector` 分别绑定同一 `sourceId/rpInstanceId/rpUserId`，
其中 `rpRegistration=true` 仅允许登记该实例用户的连接；旧版按渠道授权仍兼容。
RP 绑定与渠道独立比较版本，选定模型不写入共享模型目录。归档使用中心六类原因。

### 双方各负责什么

服务方负责稳定连接 ID、版本、变化记录、受限凭据存取、冲突结果和调用入库。酒馆方负责原生保存流程、原生连接 ID 映射、本地待发队列、接收变更、应用回执和被动调用采集。

同步内容分两层：共享渠道保存 API 地址、协议、凭据引用和限制标签；酒馆绑定保存连接名称、选定模型、必要覆盖项、自身启停、备注及排序。选定模型不覆盖 New API 模型列表。共享字段修改展示受影响绑定，不改变酒馆当前选择。渠道和绑定分别比较配置版本。

WebUI 按通用、生图、视频、酒馆隔离；用于 RP 的连接移入酒馆，酒馆分组不导入 New API。禁止测活、禁止代码、禁止 NSFW、仅代码、客户端限定按中心标签呈现并用于绑定检查，不能由“RP”自动推断。旧 RP 迁入的禁止测活／禁止代码保留，新移入酒馆的渠道不自动加这两个标签。

角色卡、世界书、提示词、采样预设和未保存草稿继续归酒馆。保存、导入、排序、同步和连接列表刷新均不访问 RP 上游。

### 酒馆保存后同步到中心

1. 原生保存成功，记录 `instanceId + nativeConnectionId`、本地保存版本和中心基线版本。
2. 将已保存字段加入本地队列，通过 `POST /api/v1/rp/{channelId}/saved` 上报 `{eventId,expectedVersion,patch,profileId,device}`；`patch` 包含 `baseUrl,protocol,models` 以及可选 `name,order,enabled`。先在中心绑定稳定渠道 ID；新增原生连接先建立中心关联，不凭地址自动合并。更换调用 key 时可附独立 `credential` 字段，加密保存且不写入事件。
3. 服务确认保存后移除队列项；网络失败只重交事件，不重复执行原生保存或上游调用。
4. 来源事件标识用于识别回声；服务下发并由酒馆保存的变更不再次作为用户新修改循环上报。

### 中心保存后同步到酒馆

酒馆使用独立 `connector` 凭据（绑定 `sourceId,target=sillytavern,channelIds`）轮询 `GET /api/v2/connector/jobs`。任务包含 `id,lease,revision,payload,expected,force`；配置和凭据只交付授权的 RP 连接。原生保存后通过 `POST /api/v2/connector/receipts` 回报 `{id,lease,state,remoteId,snapshot,reason}`，`state` 为 `applied/waiting/failed/conflict`。租约默认两分钟；重复回执幂等。插件离线保留待办，保存结果先本地持久化再回执。`payload.switchCurrent=false`，原生凭据引用通过 `nativeCredentialReference` 复用。正在生成的请求保留已取得的连接配置；变更用于后续请求，不切换当前选中的连接。

同一连接两边都基于旧版本修改时，服务返回冲突及两侧差异。保留酒馆已经保存的内容，由用户选择采用哪一侧或合并字段，再以当前版本保存。凭据差异只显示是否更换，不展示明文。

暂停／移除共享连接通过明确变更同步，不把“某次列表中没出现”解释成删除。移除当前选中连接时提示用户另选，不自动切换。

### 真实调用回传

使用绑定具体连接的 `rp` 凭据，通过 `POST /api/v1/rp/calls` 上报。在实际请求开始时记住本次连接和模型；终态时上报来源事件 ID、实例和连接映射、请求关联、开始结束时间、成功／失败／取消、错误类别，以及实际可取得的首字和总耗时。流式中断和未知终态分别记录。

不上传对话正文、提示词或完整响应。调用结果离线补交按事件去重；已有历史没有终态的保留未知。中心可展示 RP 表现，不因此自动替换模型或启停 RP 连接。

**完成条件**：两端分别保存能在另一端看到；离线补交和冲突可处理；当前选择保持；真实调用只入库一次；所有编辑同步操作均未发起上游请求。酒馆 agent 拥有其仓库实现，本项目不修改其重构工作区。

## 给 cron 接入方：绑定已有任务，保留原调度

### 适配现有任务，而不是创建第二份任务

任务目录返回来源、稳定任务 ID、名称、计划时区、启停、是否可传入单次渠道模型、可取得的执行结果。配置界面只把可用能力展示为可选动作。

绑定保存任务引用、指定渠道与模型、额度／时间条件和明确的运行时间调整。任务正文、投递位置、重试及暂停状态仍由原调度层管理。保存绑定不执行任务，不恢复原本暂停的 cron。

资源服务提出某次运行所需的渠道配置与关联 ID，现有执行层按单次运行参数使用，不改整个 Hermes profile 的默认模型。不能隔离单次模型配置的任务先标记为暂不能用于渠道验证，由适配器补齐后开放。

真实定时执行优先用于验证。验证不能为了凑样本重复发送日报、通知或执行有副作用的任务；额外执行必须使用该任务支持的预览／不投递方式，或专门的小任务。

### 让结果确实属于被测渠道

一次验证关联 `operationId, bindingId, taskRef, runId, channelId, modelId`。网关请求关联和实际渠道 ID 尽量一起回传。

结果包含执行终态、任务验收结果、是否切换备用、实际渠道模型与耗时。没有请求级采集就标记缺口；任务整体成功但备用渠道完成，不算原渠道通过。

资源窗口关闭而任务已到期时，执行层遵循该任务已有的跳过／备用策略并记录原因。资源服务不自行替用户换模型。站点仅公布投放时刻时，只记录时刻及探查结果，不推测窗口结束时间。

**资源服务方**提供任务目录与绑定 API、验证关联和结果接收；**cron 适配方**对接真实执行入口、单次参数和回执。第二阶段先选一个合适的文字任务贯通，再接入其他任务。生图／视频待 image-caption 完成后复用相同关联方式，按实际生成终态验收。

## All API Hub：继续负责浏览器内的事

复用现有逐账号上报队列，覆盖已有自动、重试和手动签到路径。新服务承接原 `/api/v1/ingest` 格式、授权与确认语义，再逐步增加需要的字段。

账号观察和签到结果分开：签到成功但奖励未知，保持成功及奖励未确认；浏览器离线意味着资料未更新，不代表站点失效。

新增账号自动形成资源资料或待关联项；已有调用 key 由插件凭据库和原生读取流程通过专用接口交付，取不到时才列为待补，不把登录 token 当成推理 key。来源更新不覆盖人工用途、权益规则或评价。原人工／书签／酒馆来源形成的连接关联和限制标签保留，不因新来源创建无标签副本绕过禁止测活。

需要重新登录或手动签到时，WebUI、Hub 和 MCP 获得相同的站点地址和处理原因。第一阶段不新增从服务远程控制浏览器签到的系统。

## 网关与客户端：统一普通资源，保留必要例外

从 New API 读取来源渠道、模型和调用事实，关联现有资源。CPA 当前仅用于订阅反代，第一版不接入；New API 转向 CPA 的内部转发条目不进入公益站扫描与评价。

恢复通过的模型后更新 New API，回读确认地址、模型、启停及托管的优先级字段。保存、应用中、已生效和外部配置冲突分开。外部手改托管字段时保留差异，由用户决定采用外部值还是恢复规则，不持续覆盖。

当日额度优先和质量提降权只影响满足同一请求模型与能力的渠道。余额、限流和窗口影响当前可用性，不直接降低长期模型质量。统计缺样本或采集不完整时显示证据范围，不能用站方指标冒充自己的调用成功率。

CC Switch／Magpie 继续使用 New API 聚合入口。仅在对应客户端经 New API 中转仍不可用时提供专用配置，保留客户端特征、协议和请求头。配置生成、客户端接收、实际应用、任务验证分别记录，不自动切换当前配置，也不默认同步各设备的全部配置库。

旧资料中的客户端透传结论是复用线索，接入时按当前客户端、网关配置和渠道做针对性验证，不把历史结论推广到所有限定站点。

## Token Monitor：关联已有统计

网关和酒馆调用事实用于渠道可用性与质量评价；Token Monitor 继续提供工具、设备和用量视角。保存可识别的调用身份与任务关联，具备请求关联时关联展示；无法确认同一请求的来源不直接相加。

额度扣减、实际支出和估算费用保持原单位及口径。生图／视频记录生成数量、任务状态等实际指标，不伪造成 Token 数。接入时核对 Token Monitor 当前可提供的关联字段，缺失部分只标注，不补造。
