# 多设备与客户端配置同步

你在中心改一条渠道后，已分配的设备应能收到更新；每台设备上的 Claude Code、Codex 等客户端保留自己的选择。查看某条连接时，应能直接看到哪些设备已收到、哪些客户端已应用、哪里还要处理。

推荐：**中心管理资源和分配，Magpie 接收中心配置并使用已有客户端适配，原生 WebDAV 继续同步个人配置与 Library。** 中心配置作为独立来源接入 Magpie，不混进原生的整套配置双向同步。RP 沿用酒馆集成。

## Magpie 原生同步能做什么

2026-10-15 核查了本机 0.1.1244 和官方同版本源码。本机已开启 WebDAV，`keys`、`agents` 均为 true。本轮只读，没有更改配置或写入 WebDAV。

| 能力           | 实际行为                                                               | 对本需求的意义                             |
| -------------- | ---------------------------------------------------------------------- | ------------------------------------------ |
| 跨设备共享     | 同步供应商、设置、预设、Agent 模型与 Library；可携带 API key           | 多台个人设备共用同一套配置时可以直接复用   |
| 自动同步       | 网关运行时默认每三分钟同步，可手动触发                                 | 适合低频配置更新，不是实时应用回执         |
| 并发处理       | 使用远端版本条件写入；双方修改同一分区时保留较新分区，并保存被替换副本 | 不会逐条合并两台机器各自修改的供应商       |
| 同步范围       | 可排除 key、Agent 模型、Library；当前没有中心托管供应商的独立同步范围  | 不能靠一个勾选项实现按设备分配连接和凭据   |
| 本机客户端适配 | 原生格式写入、模型目录更新、配置漂移检查及原配置恢复                   | 应直接复用，不为各客户端另写一套文件生成器 |
| 登录迁移       | 备份携带配置，不携带订阅登录；其他机器需要自己登录                     | 不把“已同步”当作登录和调用已可用           |

供应商冲突以整个 `providers` 分区处理，其中还包含组与顺序。`agents=true` 则会同步 Agent 字段，可能把另一台设备的当前模型带过来。仅设 `agents=false` 可以保留设备选择，但仍缺少中心发布、分配范围和客户端回执。

**原生同步足够共享同一套个人配置；完整的中心托管还需要一层 Magpie 集成。** 不让中心直接改写 WebDAV 加密备份：那会把按连接管理重新变成整套配置竞争，也无法准确知道客户端是否应用。

## 调用路径与分发范围

| 资源                     | 调用路径                                                                         | 发给客户端的内容                                                           |
| ------------------------ | -------------------------------------------------------------------------------- | -------------------------------------------------------------------------- |
| 通用、生图/视频          | 应用 → 本机 Magpie（使用它的客户端）→ fn 网关 → 上游；其他应用可直接访问 fn 网关 | 稳定网关地址、选定模型、应用专用推理身份，不下发全部上游 key               |
| 限定客户端的 Code        | 原客户端 → 本机 Magpie → 对应上游                                                | 原协议、地址、推理 key、请求头及客户端兼容设置，仅分配给需要的设备和客户端 |
| RP                       | 酒馆 → 上游                                                                      | 仅发到明确绑定的酒馆实例，继续手动管理和禁测活                             |
| fn 上的 Hermes Chat/Cron | 对应任务 → fn 网关；已由 Magpie 管理的实例沿用其入口                             | Chat/Cron 分开调用身份和绑定                                               |

fn 调整普通渠道的优先级、权重和额度选路时，客户端入口保持稳定。只有客户端实际需要的地址、模型、凭据或兼容设置改变，才产生新的配置发布。185 条资源不意味着每个客户端都接收 185 条供应商配置。

Magpie 可以承接限定客户端资源；“Claude Code 限定”仍记录为 Claude Code，Magpie 是使用路径。不能因为能导入 Magpie，就把它变成所有 Agent 通用的资源。

## 配置归属

| 配置                                 | 修改入口和归属                         | 同步方式                                             |
| ------------------------------------ | -------------------------------------- | ---------------------------------------------------- |
| 渠道地址、认证、模型范围、限制和用途 | 中心                                   | 分配给需要的设备，由 Magpie 配置源领取               |
| 设备上哪个应用使用哪条中心连接       | 中心的设备绑定；也可在 Magpie 提交修改 | 按设备和应用发布，版本冲突展示差异                   |
| 当前手动选择                         | Magpie/原客户端                        | 默认保持本机选择；明确选择“跟随中心”后才应用中心绑定 |
| 个人供应商、个人预设、Library        | Magpie                                 | 保留原生 WebDAV 同步                                 |
| 官方登录、本机路径、代理和进程状态   | 对应设备                               | 在本机维护，由原生适配读取                           |
| RP 连接与当前酒馆选择                | 中心和酒馆已有集成                     | 沿用 RP 的保存、差异与手动应用流程                   |

设备接入时先列出当前配置及分配预览，不自动连接所有已安装客户端。只对用户明确接管的应用启用“跟随中心”。未接管应用的入口、默认模型和登录方式继续由原工具管理。

## 中心与 Magpie 的闭环

1. 在中心为设备分配连接，为应用选择“本机选择”或“跟随中心”。预览显示将新增的供应商、改变的应用绑定及需要的推理凭据。
2. Magpie 以该设备的凭据读取分配配置。默认每三分钟检查一次版本；打开界面或点“立即同步”时立即读取。没有变化不重新写客户端文件。
3. Magpie 校验并保存该来源的完整配置后，更新现有模型目录。配置缓存放在独立文件中，断网和中心停机时继续使用最后成功保存的配置。
4. 对“本机选择”只更新可用连接；不替换当前选择。对“跟随中心”调用已有 Agent 字段应用流程，将指定连接写到该应用。
5. 回读实际字段后上报结果。应用文件已写入但运行中的客户端需重启/新建会话时，直接显示这项操作。无法确认进程加载时保留“已写入配置，运行状态待确认”。
6. 后续真实任务成功才登记该设备、客户端、连接版本的验证结果。没有调用证据时显示“未验证”，同步流程不自动发推理请求。

不把不同层次拼成一个“成功”：中心已保存、设备已收到、客户端已应用、真实任务已验证分别展示。新版本下发后保留旧版本验证的时间和对应版本，不冒充新版本的验证。

### 本机修改与冲突

在 Magpie 中修改中心管理的连接，提交中心现有连接版本；中心保存后再发布。保留本机选择时，仅上报当前使用情况，不修改其他设备的默认值。

客户端原生配置被外部工具修改后，复用 Magpie 的漂移检测：显示实际连接和中心绑定，暂停该绑定的自动覆盖。用户可“采用本机选择”或“应用中心配置”。旧版本修改收到冲突时保留本机已保存内容，不能用时间戳较新替代版本检查。

一台设备失败不阻止其他设备应用。关闭或移除某条连接时，显示受影响应用；当前正在进行的任务保持原连接，之后是否切换由该应用已确认的绑定规则决定。

## 与原生 WebDAV 共存的实现

需要在 Magpie 增加一个轻量的“AI 资源中心”配置源；当前版本没有此功能。这是首选开发方式，不能宣称现有 WebDAV 已能完成。

- 中心供应商单独缓存在配置源文件中，复用中心连接的稳定标识。运行时参与 Magpie 的供应商目录与已有协议转发；不写进个人供应商存储。
- 原生备份/同步继续收集个人供应商，不携带配置源缓存、设备凭据或中心推理 key。中心连接由每台设备重新领取，避免把某台设备的凭据经 WebDAV 发给其他设备。
- 对明确“跟随中心”的 Agent 字段，在原生快照收集和远端恢复时排除这些字段。其他 Agent 字段按现有同步设置处理。不能只在上传时排除，而让旧备份恢复又覆盖回来。
- 中心绑定所需的模型目录由现有目录刷新机制重建。个人预设可引用连接，但应用预设涉及中心绑定时应转为可见的本机修改，交由上述冲突处理。
- 复用 Magpie 的原生字段写入、漂移、回读和恢复能力。配置源失效不清空缓存，配置应用失败保留错误；不启动第二个写同一客户端配置的后台工具。

因此新增的是一个配置源、绑定归属和上报接点，不是另一套客户端适配器或 WebDAV 协议。官方的供应商插件负责订阅登录与请求执行，不直接假定它就是现成的配置源接口；实现应接在供应商目录、Agent 应用和备份范围这几个位置。

原生整套配置恢复仍可作为用户主动操作。对中心托管字段先显示影响；解除对应绑定后才能由整套恢复接管。该限制仅适用于新接管字段，既有个人配置的恢复流程保持原有含义。

## 限定客户端的兼容设置

Magpie 0.1.1244 提供 `passUserAgent`。开启时转发原客户端的 User-Agent；默认关闭时使用 Magpie 的标识。客户端自己没有发送的标识不会凭空出现，手填的 User-Agent 请求头则优先于此选项。

中心发布客户端限定资源时启用原客户端标识透传，保留已有请求头，使用相同的原生协议入口。Codex 资源若明确要求原始请求特征，再启用已有 `codexAsSent`，不对所有连接统一启用。真实验证从对应客户端经 Magpie 发起。

限定客户端资源使用中心已选定的模型，领取和保存不触发模型目录刷新。Magpie 当前 CLI 新增供应商以及管理页新增/换 key 的保存流程会尝试拉取模型；配置源应接入底层目录与应用能力，不能直接套用这些带网络请求的入口。Magpie 自己拉目录时没有原客户端的 User-Agent，失败不能用来判定原客户端不可用。

Magpie 原生供应商字段需要正确映射：

| 中心字段                              | Magpie 字段                                                                         |
| ------------------------------------- | ----------------------------------------------------------------------------------- |
| OpenAI / OpenAI Responses / Anthropic | `baseAPI` 分别为 `chat` / `responses` / `anthropic`                                 |
| 协议地址                              | `chat`、`responses`、`anthropic` 中对应的 URL；Anthropic 使用根地址，避免重复 `/v1` |
| 认证方式                              | `authHeader` 对应实际认证方式，推理 key 单独保存                                    |
| 自定义请求头                          | `headers`，保留真实所需字段                                                         |
| 客户端标识                            | 客户端限定资源的 `passUserAgent: true`                                              |

当前中心允许客户端限定渠道导出到 Magpie，但导出映射还需补齐上述标识、认证与地址规范，并纠正 `baseAPI` 的枚举含义。这些是同步接入前要修正的现有导出问题，不以“文件已生成”作为兼容验收。

普通 API key 的这些字段不能替代官方订阅登录。RP 不进入此配置源、目录自动请求或验证任务。

## 中心需要保存什么

沿用现有连接、凭据和修改记录，新增设备及其应用绑定、发布回执即可，不复制每个应用的整个配置文件。

| 记录     | 必要内容                                                                  |
| -------- | ------------------------------------------------------------------------- |
| 设备     | 名称、稳定标识、领取凭据摘要、最近联系时间、Magpie 版本                   |
| 应用绑定 | 设备、客户端、中心连接、选定模型、本机选择/跟随中心、版本                 |
| 发布     | 该设备的配置版本、关联连接版本、显式移除项                                |
| 回执     | 设备收到版本；每个绑定的应用结果、实际连接、错误、需重启/新会话说明和时间 |
| 验证     | 设备、客户端、连接版本、真实任务结果与时间；复用现有评估/修改记录         |

每个应用保留独立 fn 推理身份；需要按设备区分网关调用时，再由设备绑定取得该应用在此设备上的身份。客户端限定上游使用分配的上游 key。设备领取接口仅返回该设备被分配的连接，不提供网关管理凭据。

接口补充如下，均为待实现接口：

| 接口                                  | 用途                                                   |
| ------------------------------------- | ------------------------------------------------------ |
| `GET /api/v1/devices`                 | 管理界面查看设备、应用绑定与最近回执                   |
| `POST /api/v1/devices`                | 注册设备，返回一次性可见的设备领取凭据                 |
| `PATCH /api/v1/devices/:id/bindings`  | 携带版本保存该设备的应用绑定                           |
| `GET /api/v1/device-config`           | 用设备凭据领取分配配置，以配置版本/ETag 支持无变化响应 |
| `POST /api/v1/device-receipts`        | 按配置版本和绑定幂等上报收到、应用及错误结果           |
| `POST /api/v1/device-binding-changes` | Magpie 提交本机保存的绑定变更及预期版本                |

设备凭据只能领取自己的配置、提交自身绑定变化及回执。凭据撤销后停止领取；撤销领取凭据不等于已从离线设备删除上游 key。需要撤销调用权限时，应同时轮换/停用对应推理身份，并显示离线设备待清理。

## 界面

“设置”增加“设备与客户端”。每设备一行：设备名、最近联系、已收到版本、已应用/待处理应用数量；展开直接显示每个应用的当前连接、管理方式、应用结果及错误。离线由最近联系时间判断，不伪造一次失败。

资源详情的“分配到设备”选择目标设备和应用，预览改动再保存。客户端限定资源仅提供符合限制的客户端选项，Magpie 显示为使用路径。当前入口与新入口的地址直接可点，凭据只显示掩码。

Magpie 中显示“来源：AI 资源中心”、最近同步和当前管理方式；支持立即同步、提交修改、采用本机选择和查看冲突。个人供应商继续在原界面维护，不在中心复制一套编辑页。

酒馆继续使用现有 RP 面板，不要求安装 Magpie。不受 Magpie 支持的应用保留现有原生配置导出，显示手动应用状态；不能把导出或用户下载当作客户端已应用。

## 开发与验收

中心增加设备分配和发布/回执接口；Magpie 增加独立配置源、托管字段范围和既有应用流程的回执。原导出先修正原生字段映射，再用同一映射生成配置源内容。前端增加设备页和分配预览。RP 复用现有链路。

在两个隔离设备目录和本地上游 stub 中验证：

- 同一连接更新到两台设备，各自默认模型保持独立；只分配给一台设备的 key 不出现在另一台的配置或 WebDAV 备份。
- 个人供应商和 Library 的原生同步仍有效；旧备份恢复不会覆盖已接管字段，解除绑定后可恢复原有流程。
- 离线继续使用已缓存配置，恢复后领取新版本；重复回执不制造重复结果。
- 客户端原生配置被外部修改时展示差异，不被定时任务反复覆盖；部分应用失败可单独重试。
- 真实 Claude Code/Codex 经 Magpie 访问本地 stub，原客户端标识、所需请求头、协议路径及认证正确；配置发布不额外推理。
- 中心停机不影响原网关、已配置客户端或酒馆；RP 导入、编辑、同步的上游请求数为零。

本轮完成设计和源码核查，未实现配置源或多设备回执，也未改动生产同步设置。
