# AI 资源管理中心详细设计

## 资源与调用边界

站点聚合账号和渠道。分类沿用通用、生图/视频、RP、客户端绑定（Code）；分类与应用绑定分开。GPT/DeepSeek 推荐 Code，Claude/Kimi 推荐 RP，推荐不自动迁移用途。

channel.accessMode 为 gateway、rp_direct 或 client_bound。gateway 绑定 New API/CPA；rp_direct 只绑定酒馆、禁推理和目录测活；client_bound 保存适用客户端、协议、请求头和实际验证结果。非 RP 网关资源可绑定多个应用，各应用使用不同推理身份。客户端绑定资源按实际客户端条件维护。

## 存储

SQLite WAL、事务写入。业务标识内部使用 UUID，来源引用稳定关联，界面显示直接网址而非编号。下面描述业务对象；实现使用 `entities(kind,id,data,version)` 保存站点、账号、连接、评估和应用身份，不为每个对象建立重复的映射表。权益归账号，不能按模型拆出多份余额。

事实单独保存：`events` 以来源事件 ID 唯一去重；`calls` 以来源及来源记录 ID 联合唯一；`refs` 关联来源标识；`actions` 保留必要修改与回执；`credentials` 保存加密凭据；`auth` 只保存访问凭据摘要。版本检查、事实接收和账号合并在 SQLite 事务内完成。

sites：名称、网站地址、签到入口、别名、来源链接。
accounts：site_id、外部账号关联、显示名、账号状态。
channels：account_id、分类、access_mode、base_url、protocol、选定模型、凭据引用、应用绑定、manual_enabled、自动/人工管理、人工评价、排序、版本、网关绑定及托管字段回读值。
entitlements：account_id、额度池类型、余额、单位、valid_until、重置时区/时刻、签到门槛、投放时刻、可用窗口、规则原文、来源与确认时间。
checkins：独立事件标识、account_id、实际发生时间、业务日期、执行方式、结果、原因及已确认奖励。
calls：来源唯一记录标识、channel_id、model、request_id、token_id、发生时间、结果、延迟、流式状态、错误分类和摘要；不保存正文或费用账本。
evaluations：渠道、模型、客户端、任务标题、准备/执行/结束状态、执行区间、专用 token 引用、任务摘要及人工评价。
actions：修改字段、必要回退值、实际结果与错误。
settings：来源接入、评价阈值与 Token Monitor 链接。

凭据在 fn 加密存储，主密钥放部署秘密文件。列表仅返回有无凭据和掩码，显式配置导出才解密所需推理凭据。上报凭据不能读凭据或修改网关。

## 来源与导入

All API Hub 拥有账号观察与签到事实；中心拥有用途、模型选择、权益规则和评价；网关拥有实际配置；酒馆拥有原生保存和当前连接选择。

来源标识优先匹配，规范地址和凭据指纹辅助。OpenAI `/v1` 规范化用于匹配，不合并不同 key。无法唯一关联时进入待关联，不猜账号。导入预览展示新增、合并、冲突和缺 key。预览存储加密的凭据引用，待关联项可重新打开，不要求重复上传。来源更新保留人工字段。历史可用记录保留来源与日期，不计入自动评分样本。

导入的连接显示“已记录”，没有配置操作就不制造“待应用”任务。首次导入的网关连接保留原配置及人工模式；用户在渠道详情选择自动托管并应用后，才进入自动调整。新增通用/生图连接可用“接入 New API”建立渠道，创建前后按稳定标签核对，回读一致后转为自动管理；不创建 RP 或客户端绑定渠道。

表格读取网址超链接及用户补充 key，Notion 迁入规则原文和来源链接。酒馆保存的 RP 连接仅导入，不测活。归档保留问题原因，恢复使用真实任务或人工确认；网站、API、key、额度、限流和签到分别表达。

## API

GET /api/v1/overview：今日权益、签到、候选连接与待办。
GET /api/v1/sites：聚合资源，支持搜索、分类及问题过滤。
PATCH /api/v1/channels/:id：expectedVersion + 明确变更字段；冲突返回 409 和最新版本。
POST /api/v1/ingest：批量账号观察与签到事件，eventId 唯一，返回 acknowledgedIds。
POST /api/v1/channels/:id/apply：应用托管字段，返回 observed 与 error。
POST /api/v1/evaluations：指定渠道/模型/客户端，准备专用连接。
PATCH /api/v1/evaluations/:id：登记执行区间、结束摘要和评价。
POST /api/v1/exports：生成 Magpie/目标客户端配置，包含协议及经过校验的请求头。

POST /api/v1/channels/:id/connect-gateway：将已有、具备 key 和选定模型的通用/生图连接接入指定 New API；不发推理请求。
POST /api/v1/accounts/:id/merge：关联同一站点内重复账号，重连来源、连接和历史，保留较新的余额与人工权益规则。
GET /api/v1/imports/:id：恢复未完成导入；POST 对应 commit 接口只提交选定条目。
POST /api/v1/channels/:id/clear-issue：人工确认后清除记录的调用问题；网站问题在站点编辑中独立处理，不据此生成成功样本。
GET /api/v1/rp/connections、GET /api/v1/rp/:id/config、POST /api/v1/rp/:id/saved：酒馆限定范围读取与保存回执。saved 携带 eventId、expectedVersion、原生 profileId 和明确连接字段。

Web 管理会话、扩展仅上报 token、酒馆限定绑定 token 分开。仅用户配置的来源被访问。修改由数据库版本串行，来源接口回读确认。托管值与外部修改不一致时记录差异并暂停覆盖，用户可采用外部配置或恢复中心规则。

## 签到与权益

扩展逐账号结果进入本地持久队列；fn 事务确认后删除，断网补交不重签。自动、重试、手动、快速签到使用同一上报服务。签到结果与余额观察分开；奖励未知显示待确认。

以实际发生时间和已确认账号时区推导业务日期。到期规则未确认时不猜。每日额度与长期额度是不同池。投放时刻与可用窗口分开，AgentRouter 10:00/19:00 不推导结束时间。签到门槛支持明确的余额上限，其余原文保留。

接收时间不替代观察时间；补交的旧观察保留为历史，不覆盖较新余额、账号状态或已知当日截止时间。历史备份导入不更新执行设备在线状态。上报成功只能证明交付成功，不能把旧余额解释为当日刷新。

## 评价与路由

每分钟增量同步消费/错误日志和异步任务最终状态；每小时评价；权益变化和评估结束立即计算。以来源记录标识去重；重试产生的真实上游尝试归所属渠道，不把尝试数称为用户任务数。只统计选定模型与有效上游结果，取消、输入问题、额度、限流、账号验证、窗口外不作为长期质量差。缺失字段和采集缺口不补零；New API 的非正首字延迟作为缺失处理。

分钟任务同时比较已确认的额度截止时间和可用窗口边界，不等到下一次小时任务才退出优先池。自动托管保留接管时的优先级/权重基准；临时限额恢复且样本不足时恢复基准，不把临时 0 优先级永久留下。进程重启后的首次分钟任务重新核对当前可用性。

CPA 使用当前部署的 Manager `/v0/management/monitoring/analytics` 持久记录，不读取破坏性消费队列；只关联 OpenAI compatibility 提供者，排除账号反代。自动提降权只写 New API，CPA 配置继续人工维护。新关联网关从最近七天回填，避免沿用旧游标遗漏已有记录。

默认 7 天窗口、30 条样本。少于 30 待评价并保留配置；≥98% 优先；95%～98% 常规；<95% 备用。人工较差不能自动提权，人工固定保留值。图像/视频提交成功为 pending，仅最终完成进入成功样本。

先筛可用性、协议能力和应用匹配，再选达标当日额度。New API priority：当日优先400、当日常规300、长期优先200、长期常规100、备用0。权重默认100；文字模型以同模型成功记录首字延迟的相对同组中位数比值，在选定模型间平均，权重取 round(100*ratio) 并限制50～200；无可比样本比值1。图像视频权重100。

结果未改变不重复写入。可用性导致的停用保留 manual_enabled，恢复不覆盖人工暂停。评价不发合成推理或签到请求。初始导入保留原配置，达到条件的托管渠道才调整。部署时核对原网关主动测试设置，避免新增测活。

网站故障、记录的调用问题和人工启停分别保留。暂停不能盖住原始 API 错误；真实调用成功可以清除调用问题，但不自动恢复人工暂停。来源记录重复读取不撤销用户的人工清除。New API 写回保留不归中心管理的原生配置，回读不一致直接报错；更新 key 时保存旧凭据引用，提交后仍等待真实调用确认，不因配置回读而声称 key 已验证。

## 评估和客户端

评估是配置准备与结果登记，不启动 Agent。New API 使用管理员所属的专用推理 token 加固定渠道标识，当前版本 single_attempt，结束停用专用 token。网关管理 token 不导出。固定能力缺失直接报错，不偷偷切换上游。

client_bound 保留客户端、认证方式、协议、地址、headers 和模型配置；借鉴 CC Switch 请求头校验，认证及传输头由连接机制管理，其他覆盖字段名称大小写统一、值为合法字符串。Magpie 导出使用现有 provider 字段。Claude Code 导出移除地址末尾的 `/v1`，避免原生 SDK 再次拼接为 `/v1/v1/messages`；真实 CLI 验证保留认证与自定义请求头并访问 `/v1/messages`。配置生成与客户端真实验证分开；没有请求记录显示未采集。

限定客户端连接可经同协议的 fn 透传入口或本机 Magpie 使用，保留原客户端归属。多客户端配置复用 Magpie 原生适配与 WebDAV；集中使用 Magpie 的账号和路由时可直接使用无头 Hub/Remote Magpie。当前优先复用已有 New API 透传，不新增中心配置源或设备控制服务。隔离验证、原导出字段修正和同步规则见 [多客户端配置设计](client-config-sync.md)。

## RP 联动

中心提供添加、编辑、排序、暂停和评价。保存及导入不访问上游，不自动刷新目录或连接测试。同连接在 New API 的迁移列出影响，应用后手动停用旧网关入口以排除自动批量测试，保留回退值。

酒馆复用已有原生保存链路；保存成功后同步明确字段与 expectedVersion。未保存草稿不上传。中心修改在酒馆显示差异供应用。409 保留酒馆已保存内容并展示双方字段。不改角色卡、世界书、提示词或采样预设。测试仅在隔离实例使用合成配置和本地模型。

## 展示和验证

中文独立 Web，主导航今日、资源与连接、签到与权益、渠道评价、设置；资源内有 RP/客户端绑定视图。站点每行直接网址，问题、待办及同步结果直接可见。桌面1440/1024与手机390可操作。

验证真实业务边界：幂等、断网补交、跨日、共享余额、采样门槛、限流分离、固定渠道、请求头、版本冲突、异步最终结果、RP零上游请求、网关回读和中心停机隔离。每个来源只跑必要的受影响检查，记录真实与模拟证据。

实际运行、数据迁入和未执行的生产操作见 [交付说明](../delivery.md)。Make 使用 Claude Opus 5.5，实际文件和 20 个源码/资源正文已经接回；演示余额和表现不进入中心数据库。
