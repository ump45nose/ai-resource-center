2026-10-21。第一版接入 **All API Hub、New API**，并迁入此前扫描失败的渠道与结果，让现有 WebUI 从演示骨架变成能持续查看真实资源的管理入口。2026-10-22 已完成渠道标签、完整历史迁移、WebUI 真实资料和 New API 同步；All API Hub 的账号、余额、签到和调用 key 持续上报已实现。2026-11-06 起 RP 渠道移出中心，SillyTavern 不再接入（见[产品需求](requirements.md#rp-渠道不在中心管理)）。

## 各管一部分，中心把它们连起来

| 来源 | 接入方式 | 负责的数据 | 中心向它写什么 |
| --- | --- | --- | --- |
| All API Hub | 浏览器扩展主动上报 | 站点、账号、余额、签到、已有调用 key 及其账号关联 | 首次预览接管后，下发账号名称、签到入口和明确的启停设置 |
| New API | fn 服务通过管理 API 拉取 | 真实渠道配置、已配置模型、实际调用记录 | 下发已接管渠道配置及验证通过的模型，写入后回读确认 |
| 资源中心 | 保存关系与管理规则 | 渠道标签、应用绑定、人工状态、权益规则、选定模型、扫描验证、来源映射 | 通过标准 HTTP API／MCP 暴露相同能力 |

普通调用继续由 New API 聚合，CC Switch／Magpie 使用该入口；主动检查是否允许由“禁止测活”标签决定。RP 连接在酒馆直连上游，只在酒馆和 Chrome 书签中管理。中心不进入推理请求路径。

同一站点在页面上只出现一次，下面可以同时有插件账号和网关渠道。**共享的是关联关系，不是把几份配置互相覆盖。**

## 先迁入完整资源库，不只同步当前成功渠道

首次接入前，从旧中心最新数据迁入全部现有渠道及失败记录，包括维护、网站打不开、调用失败、模型不足、限流、余额耗尽、缺 key／key 失效和不稳定归档。保留稳定 ID、来源映射、凭据引用、历次扫描／任务结果、人工限制及发生时间。旧扫描报告和表格只补充旧库缺失的历史，不覆盖较新的人工修改。

New API 和插件中已不存在的失败渠道仍留在中心，不因同步清单缺项消失。“待恢复”是同一资源库的筛选视图，展示最近原因、最后检查、下次检查和阻塞项。

| 失败情况 | 后续维护方式 |
| --- | --- |
| 维护、关闭、无模型、调用失败或不稳定 | 进入定期复查；目录与扫描出现候选后，用合适任务验证，成功后恢复对应模型并同步 New API |
| 限流或限时投放 | 按已知重置／投放规则安排复查，不持续重试 |
| 余额耗尽 | 优先接收签到／余额更新；有额度来源时继续恢复，无法补充的保留归档原因，不跑耗额任务 |
| 缺 key、确认失效、未注册 | 展示具体待补条件；已有有效凭据或账号更新后再继续模型验证 |
| 禁止测活 | 不进入主动复查链；接收真实调用、来源资料和人工更新 |
| 明确删除／禁止使用 | 保留历史，不参加自动恢复 |

本轮已迁入失败渠道和复查资料；定期扫描、任务验证与自动恢复在维护流程启用时运行。网页失败和 API 失败分别保留，网页打不开不阻断允许进行的 API 检查。

## 用标签决定限制，不再用 RP／Code 分组代替规则

渠道按通用、生图、视频三个管理分组隔离；能力、限制标签、实际应用记录分别保存。标签包括“客户端限定、禁止测活、禁止代码、禁止 NSFW、仅能用于代码”，含义与迁移规则以[产品需求](requirements.md#三个用途入口限制放在状态列)为准。

- 同一渠道关联到插件和 New API 时沿用同一份限制，不创建无标签副本绕过规则；同站独立 key 的限制分开。
- 插件刷新与网关清单更新不清空人工标签。恢复时也不清空标签，验证任务和分发目标必须符合限制。

## All API Hub：一次接入，之后跟随原有操作更新

### 第一次怎么接

在中心“接入与同步 → All API Hub → 接入设置”生成接入文件；在插件“设置 → 通知 → AI 资源中心”导入文件并点击“同步账号与 key”。配对后自动接收该来源的资料，不再逐条确认。接入文件只授予对应来源的上报权限，不能读取管理资料或修改网关。

清单包括：

- 站点名称、网站、独立签到地址、账号 ID、站点类型、账号启停。
- 余额、原始单位、观察时间；已有签到方式、开关和最近结果。
- API 凭据库中已有的调用配置：凭据 ID、地址、协议、请求头、模型限制，以及原生账号／key 关联。
- 账号中已有但尚未进入凭据库的调用 key：复用插件原生读取与解析流程；需要安全验证时在插件完成，不自动创建新 key。

账号登录 token、Cookie 不交给中心。调用 key 通过专用接入口交付，fn 加密保存，清单预览、普通查询和 MCP 只显示凭据状态。同账号多把 key 作为账号凭据分别保存并保留各自限制，不按 key 数量复制渠道；已有渠道保留原选定 key，不用插件中新出现的另一把 key 覆盖。新账号仅在单把 key 可明确使用时创建暂停的连接，多 key 未选定时先展示账号资料。未取得调用 key 的账号仍可展示余额和签到。

### 日常如何更新

| 发生什么 | 交给中心什么 |
| --- | --- |
| 新增／保存账号，或插件云同步完成 | 更新后的来源清单与明确的移除记录 |
| 刷新余额 | 带观察时间和单位的账号余额 |
| 自动签到、重试、手动执行、快速签到结束 | 原执行结果、业务日期、时区、原因、已确认奖励 |
| 保存／更换调用凭据 | 凭据与关联变化，走专用交付路径 |
| 插件启动 | 核对清单，补交待发记录 |

复用现有本地队列，事件产生后投递；后台每分钟核对账号变化并补交，清单每 15 分钟发送一次心跳，中心确认保存后才移除。补交不重新签到。签到成功而奖励未知时，显示“成功，奖励待确认”。已有自动签到结果按原时间回填，插件里的人工签到标记单独展示，不冒充执行结果。

已有调用 key 每 6 小时核对；首次和手动同步每分钟处理 5 个启用账号，单账号读取最多 20 秒。暂停账号仍交付资料和余额，不访问其远程密钥接口；中心已保存的 key 保留。凭据库配置随保存变化交付。读取失败或只返回掩码时保留已有 key，并在账号详情显示问题；可在原生密钥页处理后重新同步。

来源账号 ID 优先关联；同站相同实际 key 可关联回已整理的历史账号／渠道，避免余额重复展示，保留人工名称、用途、限制和归档。新账号先显示资料，即使 key 尚在读取也不丢失；没有实际调用配置时显示“仅账号资料”，不创建占位渠道。来源移除只更新来源状态，不删除历史或恢复已移除渠道。

同一份多设备同步的账号库对应同一个逻辑来源，设备 ID 只用于区分上报端。来源 ID 和中心上报凭据不混进公共备份；恢复插件时显式配对已有来源，账号 ID 沿用原值。第一版沿用一台设备执行自动签到的安排，其他设备可以上报观察。

浏览器关闭／休眠时，中心保留最后观察时间，显示“最近未上报”，不把站点标成失效。WebDAV／Gist 继续用于插件原生备份和多设备同步；它们不共享当天签到执行状态，不能单靠备份完成签到历史接入。[All API Hub 云同步说明](https://all-api-hub.qixing1217.top/webdav-sync.html)

### 避免重复维护 New API

中心接管的渠道，由中心执行模型验证和网关更新；插件不再自动覆盖这些渠道的模型。未接管的渠道维持原管理方式。新增插件资源先进入中心待扫描列表，不因目录里列出模型就直接开放到网关。

## New API：先看清现状，再接管明确的字段

### 第一次怎么接

在 fn 配置 New API 地址、管理凭据和用户标识。检查授权后读取渠道，预览新增、已关联和待关联条目，再启用同步。管理凭据只留在 fn，浏览器通过中心访问。

使用既有管理 API：渠道 `/api/channel/`、调用 `/api/log/`。实施时按部署版本核对字段与权限，不用渠道测试接口来检查来源连接。[New API rc.45 路由](https://github.com/QuantumNous/new-api/blob/v1.0.0-rc.45/router/api-router.go)

### 拉取什么

- **渠道配置**：原生 ID、地址、渠道类型、协议、模型／映射、分组、实际启停、优先级、权重、请求头和兼容设置。保留原生类型，不把不认识的类型直接视为 OpenAI。
- **调用事实**：日志 ID、实际渠道、模型、请求关联、调用身份、发生时间、结果、可取得的首字／总耗时、流式状态与错误类别。
- **采集范围**：最近成功区间、来源日志可追溯范围、未匹配渠道数；失败日志缺失时不展示成完整成功率。

普通渠道列表不等于完整 key 导出。优先关联中心已有或插件交付的凭据；只有网关可用、没有原始 key 的渠道如实显示该状态，不标成“key 丢失”。原生多 key 渠道先按网关渠道记录，日志不能区分某把 key 时不生成该 key 的独立表现。

建议渠道配置每 **10 分钟**、调用记录每 **1 分钟**拉取，并提供“立即同步”。调用按原生日志 ID 去重，时间游标保留重叠区，整段写入后才推进。渠道与调用分别记录成功时间；一项失败不抹掉另一项已完成的结果。

New API 转发到本地 CPA 等订阅网关的条目标为内部转发，不把 NAS 地址当公益站，也不顺着它接入 CPA 账号。

### 哪些变化会写回

首次接入只读，保留当前渠道与调用路径。后续启用维护时，验证通过后才按已接管的字段更新 New API，并回读确认。

页面同时保留“网关实际配置”和“中心管理规则”。网关侧手改托管字段时显示差异，暂停覆盖该条配置，由用户采用外部值或恢复中心规则。普通轮询只更新观察，不来回覆盖。

来源同步与扫描、验证、网关写入分别启用。接入成功不会顺带开始耗额测试。是否允许扫描按“禁止测活”标签判断；同一受限连接的已确认别名和重复映射也执行该限制。

## SillyTavern：不再接入

2026-11-06 起 RP 渠道只在酒馆和 Chrome 书签中管理。双向协议从未接通，以下内容已从中心移除：`/api/v2/rp/*`、`/api/v2/ingest/rp-calls`、`resource_list_rp_connections`／`resource_update_rp_connection`、`sillytavern` 同步目标、`rp` 接入角色和绑定 `sillytavern` 的执行凭据。旧插件使用的 `/api/v1/rp/*` 统一返回 `410`（`code: gone`）并提示停用中心同步；仍持有旧凭据的执行端领取或回执任务同样得到 `410`。已有酒馆来源配置、绑定记录、历史调用和事件保留，不再展示或同步。

现有 RP 渠道由一次性迁移软移除，规则见[产品需求](requirements.md#rp-渠道不在中心管理)和[数据约束](data-contract.md#rp-渠道移出中心)。Chrome 书签的“酒馆”目录保持迁移时的条目；浏览器插件仍按镜像规则维护它已托管的书签，详见[外部对接说明](integration-handoff.md#chrome-书签酒馆目录)。

## 中心用什么规则合并这些数据

| 情况 | 处理 |
| --- | --- |
| 来源更新已有条目 | 用来源 ID 找原对象，更新该来源负责的字段 |
| 同站多来源 | 聚合为一个站点；账号独立，余额按账号／额度池显示一次 |
| 网关渠道缺账号归属 | 先保留待关联连接，不凭站点域名猜账号或余额 |
| 来源备注与人工备注不同 | 分别保存；人工标签、应用绑定、权益、暂停和评价不被来源刷新覆盖 |
| 来源明确删除条目 | 移除该来源关联，保留其他来源、人工记录和历史；不级联删除 |
| 完整清单少了条目 | 标明“来源已不再提供”，等待明确移除，不解释成 key 失效 |
| 中心明确移除／禁止使用 | 再次同步不自动恢复；维护／关闭的自动恢复另由已启用验证流程处理 |
| 来源重复或晚到上报 | 按来源与事件 ID 去重；旧观察保留历史，不覆盖较新的余额和状态 |

来源关联、观察更新、连接编辑分开记录。只有连接共享配置的改变增加其配置版本，避免正常同步不断打断编辑。

## 页面怎么用

“接入与同步”只提供两类来源：All API Hub、New API。每个来源就近展示：

- 同步方式和范围、授权状态；推送来源的最后收到时间。
- 清单、余额／签到、调用各自的最近成功时间与当前问题。
- 最近新增、更新、待关联、已移除数量，点击查看具体变化；首次迁移同时列出历史失败及待恢复渠道，不只统计当前可用渠道。
- 接入设置、首次预览、暂停同步；New API 提供“立即同步”，插件端提供本机“立即上报”。中心页不把服务器无法拉取的来源做成假按钮。

New API 首次接入预览后导入；All API Hub 在用户配对后直接接收来源资料。之后来源负责的字段自动更新，不每轮确认。来源问题留在来源卡片，网站打不开、调用失败留在对应渠道；已知维护不堆成红色待办。

站点详情显示每个字段的来源和更新时间；模型列表分别显示网关配置、个人 key 目录、站方指标与自己的验证。同步导入的模型不直接标成“已验证”。

## 接口沿用哪些，补哪些

以下路径相对中心根地址。旧入口保留原语义；“待补”是实施任务，不是已经可调用的接口。

| 能力 | 当前基础 | 本轮补齐 |
| --- | --- | --- |
| 来源配置、授权检查、预览、同步与操作查询 | `/api/v2/sources` 及其 `check/preview/sync`，`/api/v2/operations/{id}` 已有 | 完整差异预览、分项同步时间与错误、单独的同步开关 |
| 插件账号与签到上报 | `/api/v1/ingest`、`/api/v2/ingest/events` | 已补 `POST /api/v2/ingest/inventory`：账号清单、明确移除、观察时间；原签到事件继续去重确认 |
| 插件凭据交付 | 中心加密存储及单渠道凭据写入 | 已补 `POST /api/v2/ingest/credentials`：按来源账号／key ID 批次交付，仅配对来源可写；完整与部分读取分别处理 |
| 酒馆旧保存及调用 | `/api/v1/rp/*` | 已退役：返回 `410`（`code: gone`），不记录事件或调用 |

清单使用来源原生 ID、清单版本、采集时间、完整范围及条目；增量使用事件 ID 与明确动作。业务查询与管理操作继续使用同一 HTTP／MCP 能力层；来源凭据和调用 key 不进入普通 MCP 文本。

## 按能用的顺序实施

| 批次 | 做什么 | 完成后能用什么 |
| --- | --- | --- |
| WebUI + New API | 最新全量资源及失败记录迁移、旧分组转标签、同源会话与 API、真实来源页、渠道和调用同步、真实站点与模型查询；拆开同步与维护调度 | 页面能看到 fn 的真实渠道、调用和变化，刷新保留；不测试、不改网关 |
| All API Hub | 在实际使用的扩展版本合入队列，补清单、账号／key 关联和凭据交付 | 新增账号、余额、签到和已有 key 自动汇入；中心少填资料 |

2026-10-22 已完成首次全量交接，新版人工资料在新版维护。后续接入插件时按来源归属同步资料、映射与事件确认，不再用旧库全量覆盖新版人工修改。切换插件目标保留待发队列，同一来源只向一个正式中心交付；新旧服务不同时托管同一网关字段。

本轮不开发 CPA 适配、不安排模型任务、不接管业务 cron、不切换客户端。后续扫描测试在这份来源与凭据关联上开展，不再维护第二份渠道清单。

### 最后集中验收

- 新增、修改、显式移除同步正确；暂停同步不影响已有推理连接。
- 重复上报、断网补交、重启不会重复计入签到／调用；晚到余额不覆盖新观察。
- 同站聚合，独立账号余额不合并。
- 历史失败和归档原因完整接入；缺 key、缺余额、等待窗口与禁止测活分别展示，不被来源刷新清除。
- New API 渠道与调用能关联；内部订阅转发不变成公益站，日志缺口可见。
- 接入、导入、编辑、同步不产生上游请求或隐式网关写入；后续检查入口统一执行标签。
