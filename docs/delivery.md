## 自动评价与客户端配置

每分钟读取新增网关调用，每小时重新计算；权益修改、上报和评估结束也会计算。只有明确设为自动托管且已回读的 New API 连接会被调整。客户端限定连接还需完成原生透传回读，仅在适用客户端/协议组内比较；RP 和人工固定项不参与自动调整。

额度截止与可用窗口边界按分钟核对；样本不足的连接临时退出后恢复接管时的优先级。通用/生图连接必须先接入 fn 网关，才能生成应用或评估配置；不会暗中导出绕过 fn 的直连配置。

最近七天少于 30 条有效记录时保留原优先级；限流、余额、账号验证、key、输入和取消不计作长期质量失败。限流或额度问题会影响当前可用性，后续真实调用成功可恢复。没有结束时间的资源投放公告只记时刻，不推导开放窗口。

准备评估配置只创建专用推理身份并固定渠道，不会运行 Agent。请在现有客户端执行自己的任务，再登记区间和评价；结束会停用评估 token。允许转发的客户端绑定经 fn New API 的原生协议组使用，可由本机 Magpie 继续配置客户端；明确禁止转发的站点保留直连。原客户端限制继续保留，缺少请求记录显示未采集。

Magpie、Claude Code、Codex、OpenCode、Hermes Chat/Cron 的配置生成已实现。Magpie 使用协议 URL 字段，Hermes 使用原生 providers 配置；Chat/Cron 分开身份。配置生成与“人工确认真实任务成功”分开保存。未对用户所有客户端逐一执行真实任务。

2026-10-15 复核后的 [多客户端设计](design/client-config-sync.md) 改为复用 Magpie 原生同步与客户端适配，撤销新增独立配置源和设备发布/回执服务。fn 的无头 Magpie/Remote Magpie 已有集中供应商、设备密钥与选路能力；当前优先沿用 New API/CPA。使用现有 New API 镜像的隔离实例完成 4 个合成请求案例，Anthropic/Responses 正文和客户端头透传、Anthropic SSE 通过；未请求公益站，未将客户端限定连接批量迁入网关。回执见 [透传验证](verification/newapi-passthrough.json)。本轮已修正 Magpie 导出的 `baseAPI` 枚举、Anthropic 根地址和认证映射；Magpie 对 Claude Code 及远程会话已有专门的客户端特征保留路径，不能只以 `passUserAgent` 开关概括。
